## 개요

- 순서: 플랜 → 비판 검토 → 구현 → 리뷰.
- 플래너와 비판 검토는 일을 시작하기 전에 관련 프로젝트 코드부터 분석한다.
- 플랜은 비판 검토(rationale-critic)가 바로 보고 플래너에게 피드백한다. 구현 결과는 리뷰어(reviewer)가 본다.
- 각 에이전트의 세부 규칙은 이 플러그인의 `agents/<이름>.md` 가 정본이다(호출 이름은 `omni-pipeline:<이름>`). 이 문서에 다시 적지 않는다.
- 코디네이터(메인 세션)는 지적의 근거를 확인한 뒤 고칠 목록만 다음 에이전트에 넘긴다.

## 범위 고르기

- 사용자가 「플랜·비판만」이라고 하면 구현 단계는 돌리지 않는다. 플랜이 확정되면 멈추고 보고한다.
- 구현은 사용자가 따로 지시할 때만 한다.

## 역할과 재사용

| 역할 | 에이전트 정의 | 맡는 단계 | 수명 |
|---|---|---|---|
| 플래너 | `omni-pipeline:planner` | 코드 분석 → 플랜, 기록 문서 갱신 | 한 번 띄우면 계속 재사용(SendMessage) |
| 비판 검토 | `omni-pipeline:rationale-critic` | 코드 분석 → 플랜 검토 → 플래너에 피드백 | 계속 재사용 |
| 구현 | `omni-pipeline:builder` | 구현 | 작업 흐름이 끝나면 닫음. 수정 한 건마다 닫지 않음 |
| 리뷰어 | `omni-pipeline:reviewer` | 구현 결과 검토 | 계속 재사용 |

- 에이전트 정의에 model 이 있으면 Agent 호출에 model 을 넘기지 않는다.

## 단계

1. 착수 확인
   - 첫 시작은 사용자 컨펌을 받는다.
   - 승인된 작업 안의 단계 전환은 묻지 않는다.
2. 코드 분석(플래너·비판 검토 둘 다, 플랜 작성·검토 전에)
   - 근거 문서(명세·이슈)를 읽고, 그 규칙이 닿는 코드를 직접 찾아 읽는다 — 진입점, 판정 함수, 호출처, 같은 값을 따로 계산하는 곳, 관련 시험.
   - 분석 결과(파일:줄과 지금 동작)를 플래너는 플랜의 「지금 코드」 절에, 비판 검토는 검토의 근거로 쓴다. 분석 없이 기억이나 옛 플랜 문장으로 판단하지 않는다.
3. 플랜
   - 플래너가 규칙 파일의 「Agent pipeline」 절에 적힌 플랜 위치에 플랜을 쓴다(기록 집계 명령이 있으면 재생성 포함).
   - 완료 조건은 명령으로 판정할 수 있게 쓴다.
4. 비판 검토
   - 플랜이 작성되면 비판 검토가 바로 본다 — 근거 문서·코드 분석과 맞는지, 규칙마다 근거 등급(1차 출처·2차 출처·실측·추정·무근거), 빠진 호출처·시험, 범위 밖 수정.
   - 지적은 파일:줄 또는 출처 URL 과 함께 플래너에게 직접 보낸다. 반영 뒤에는 필요한 만큼 다시 검토한다.
5. 구현(지시가 있을 때만)
   - 구현 에이전트에게 플랜 경로를 준다. 시험 범위·타입 검사·커밋·DB 규칙은 builder 정의를 따른다.
   - 플랜과 다르게 한 점은 반드시 보고하게 한다.
   - 플랜·이슈 같은 기록 문서의 수정(결정 반영·상태 변경·실측 기록)은 플래너가 한다. 구현 에이전트는 코드·시험과, 플랜에 적힌 코드 관련 문서만 고친다.
6. 리뷰
   - 리뷰어가 구현 결과를 Blocker/High/Nice-to-have 와 파일:줄 근거로 낸다.
   - 코디네이터가 지적마다 인용한 파일을 다시 읽어 근거를 확인한 뒤, 고칠 목록만 구현 에이전트에게 넘긴다.
7. 마무리
   - 플랜 status·본문 체크박스·이슈 상태와, 규칙 파일의 「Agent pipeline」 절의 기록 집계 명령이 있으면 그 결과를 갱신한다 — 플래너에게 맡기고 실측 수치를 넘긴다. 구현이 끝났는데 status 가 그대로 남지 않게 한다.
   - 실 DB 확인(live 시험·실측 대조)은 코디네이터가 직접 한다.
   - 커밋은 사용자가 요청할 때만 한다.

## 비판 검토에 넘길 때 (필수)

- 진행 중인 플랜 문서 경로를 주고 **최신본을 먼저 읽게** 한다.
- 이미 플랜에 반영·결정된 항목은 「반영됨」 한 줄로만 답하게 한다.

## 사용자에게 올리는 것

- 사용자가 결정해야 할 것만, 표 하나로 모아 권장안과 함께 한 번에 올린다.
- 에이전트의 idle 알림이 앞 보고의 반복이면 「새 내용 없음」으로만 답한다.

## 흔한 실수

- 코드 분석 없이 옛 플랜·메모의 문장을 근거로 플랜을 쓰거나 검토한다.
- 리뷰 지적을 근거 확인 없이 바로 구현 에이전트에게 넘긴다.
- 구현 에이전트가 기존 시험을 지우거나 덮어쓴다. 리뷰에서 확인한다.
- 「출력 0줄」을 통과로 본다. 종료 코드를 같이 찍게 한다.
- 기록 문서 갱신(플랜·이슈 status·실측 기록)을 구현 에이전트에게 맡긴다. 플래너 몫이다.
