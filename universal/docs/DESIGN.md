# 범용 AI 프레임워크 설계

상태: **설계안 (구현 전)**. 근거 자료는 [STANDARDS.md](STANDARDS.md)를 보세요.

## 0. 범위

**목표**: 어떤 AI 코딩 에이전트(Claude Code, Codex, GitHub Copilot, Cursor, Gemini CLI 등)와 어떤 모델을 쓰든, 프로젝트에 **같은 지침·지식·안전장치·검증 절차**가 적용되게 합니다. 도구나 모델을 바꿔도 쌓아 둔 자산은 그대로 남아야 합니다.

**비목표**
- 모델 호출 SDK나 에이전트 런타임을 만들지 않습니다. 이 프레임워크는 에이전트가 일하는 **작업 환경의 표준 구조**입니다.
- 각 도구의 고유 기능을 재구현하지 않습니다. 고유 기능은 어댑터가 **연결만** 합니다.

## 1. 설계 원칙

| # | 원칙 | 내용 | 근거 |
| --- | --- | --- | --- |
| P1 | **공개 표준 우선** | 지침은 AGENTS.md, 절차 지식은 Agent Skills, 도구 연결은 MCP를 씁니다. 표준이 없는 영역만 자체 규약을 둡니다. | STANDARDS §1 |
| P2 | **단일 정본 + 어댑터** | 정본은 `AGENTS.md`와 `.agents/`입니다. 도구별 파일(`CLAUDE.md`, `.claude/`, `.cursor/` 등)은 **생성물**이므로 손으로 고치지 않습니다. | MCP 설정이 도구마다 다름 |
| P3 | **컨텍스트 예산 계층화** | 항상 로드되는 내용은 최소로 두고, 나머지는 필요할 때 로드되게 합니다. | Agent Skills 점진적 공개, Anthropic best practices |
| P4 | **강제는 모델 밖에서** | 프롬프트는 권고일 뿐입니다. 반드시 지켜야 하는 규칙은 스크립트로 강제합니다. **최종 방어선(git hooks, CI)은 어떤 AI 도구와도 무관해야** 합니다. | "hooks are deterministic … CLAUDE.md instructions are advisory" |
| P5 | **검증 가능성** | 모든 작업은 실행 가능한 검사로 끝납니다. 에이전트·사람·CI가 같은 진입점을 씁니다. | "Give Claude a way to verify its work", AGENTS.md FAQ |
| P6 | **도구·모델 중립 서술** | 정본에는 특정 도구명, 도구 API명, 모델명을 쓰지 않습니다. 기능은 능력 단위로 서술합니다("사용자에게 질문한다", "가능하면 하위 에이전트에 위임한다"). 린터로 강제합니다. | — |
| P7 | **점진적 저하** | 어떤 도구에 훅·하위 에이전트·MCP가 없어도 동작해야 합니다. 구성요소마다 대체 경로를 정의합니다. | — |
| P8 | **평가 주도** | 스킬마다 `evals/`를 두고, 여러 도구·모델에서 스킬이 있을 때와 없을 때를 비교합니다. | Agent Skills `evaluating-skills` |

## 2. 계층 모델

```text
  항상 로드 ─┐  L0  AGENTS.md (루트)              프로젝트 사실·명령·규칙, 200줄 이하
             │  L1  <dir>/AGENTS.md (하위)        범위 규칙 — "가장 가까운 파일이 우선"
  필요 시 ───┤  L2  .agents/skills/<name>/        절차 지식 (Agent Skills 표준)
             │  L3  .agents/mcp.json              외부 도구 정본 → 도구별 설정으로 렌더
  모델 밖 ───┤  L4  .agents/policies/             결정적 정책 (명령 정책, 변경 정책)
             │  L5  검증 진입점 + git hooks + CI   최종 게이트
  생성물 ────┘  L6  어댑터 출력                    CLAUDE.md, .claude/, .cursor/, .gemini/ …
```

### 개념 대응표

| 개념 | 정본 (중립) | Claude Code (✅ 확인) | 기타 도구 |
| --- | --- | --- | --- |
| 상시 지침 | `AGENTS.md` | AGENTS.md 직접 읽음 / `CLAUDE.md`에서 `@AGENTS.md` | 23개 이상 도구가 AGENTS.md 지원, Gemini CLI는 설정 필요 ✅ |
| 범위 규칙 | 하위 `AGENTS.md` | 하위 AGENTS.md 지원, 또는 `.claude/rules/` + `paths` | AGENTS.md 표준 규칙 ✅ |
| 스킬 | `.agents/skills/` | `.claude/skills/`로 복사 | `.agents/skills/` 직접 스캔 (도구별 ⚠️) |
| MCP | `.agents/mcp.json` | `.mcp.json` 렌더 | 도구별 렌더 ⚠️ |
| 명령 정책 | `.agents/policies/command/*` | PreToolUse 훅 shim | 훅 있는 도구는 shim, 없으면 L5에 의존 |
| 변경 정책 | `.agents/policies/change/*` | (공통) git pre-commit + CI | (공통) |
| 검증 | 검증 진입점 | 동일 | 동일 |
| 하위 에이전트 | 스킬 본문에서 "가능하면 위임, 아니면 새 세션 절차" | `.claude/agents/` 생성 가능 | 도구별 |

## 3. 프로젝트에 설치되는 구조

```text
<project>/
├── AGENTS.md                      # L0 정본 지침 (커밋)
├── <subdir>/AGENTS.md             # L1 범위 규칙 (선택)
├── .agents/                       # 정본 디렉터리 (커밋)
│   ├── omni.json                  # 프레임워크 설정: 버전, 활성 어댑터, 검증 명령
│   ├── omni.lock                  # 설치한 core 파일의 버전·해시 (로컬 수정 감지)
│   ├── skills/<name>/             # L2 Agent Skills (공통 + 프로젝트 전용)
│   │   ├── SKILL.md
│   │   ├── scripts/ references/ assets/
│   │   └── evals/evals.json
│   ├── mcp.json                   # L3 MCP 정본
│   └── policies/
│       ├── command/*.{sh,py}      # L4 실행 전 명령 정책 (중립 프로토콜)
│       └── change/*.{sh,py}       # L4 변경 내용 정책 (비밀·대용량 파일 등)
├── .githooks/pre-commit           # L5 change 정책 실행 (git config core.hooksPath)
├── .github/workflows/ai-guard.yml # L5 CI: 검증 + change 정책 + 생성물 동기화 검사
└── (생성물)                       # L6 어댑터 출력 — 헤더에 "generated by omni" 표기
    ├── CLAUDE.md, .claude/…
    ├── .gemini/settings.json
    └── …
```

**생성물 커밋 정책**: 기본값은 커밋입니다. 클라우드 세션처럼 저장소에 커밋된 파일만 읽는 실행 환경이 있기 때문입니다(Claude Code 클라우드 세션 문서에서 확인). CI가 `omni sync --check`로 정본과 생성물이 어긋났는지(drift)를 막습니다.

## 4. 구성요소 명세

### 4.1 AGENTS.md 템플릿
섹션은 Commands(설치·단일 테스트·전체 테스트·린트·타입체크·**검증 진입점**), Code style(기본값과 다른 것만), Workflow, Architecture(코드에서 추론할 수 없는 결정), Gotchas입니다.
Anthropic의 포함/제외 기준을 그대로 적용합니다. 줄마다 "이 줄을 지우면 에이전트가 실수하는가?"를 묻고, 아니면 지웁니다.

### 4.2 스킬
- frontmatter는 **표준 필드만** 씁니다. 이름 규칙은 표준과 Anthropic 규칙의 합집합(`--` 금지, 폴더명 일치, `claude`·`anthropic` 금지)입니다.
- 도구별 확장은 표준의 `metadata`로 표현하고 어댑터가 번역합니다.

  | `metadata` 키 | 의미 | Claude Code 어댑터 번역 |
  | --- | --- | --- |
  | `omni.invocation: manual` | 사용자가 직접 호출할 때만 실행 | `disable-model-invocation: true` |
  | `omni.arguments: "[task]"` | 인자 힌트 | `argument-hint` |
  | `omni.delegation: preferred` | 하위 에이전트 위임 권장 | `context: fork` 검토 |

- 본문 규칙(P6): 도구 API명(예: 특정 도구의 질문 도구 이름), 환경변수(`CLAUDE_*`), 모델명을 쓰지 않습니다. 대체 절차를 함께 씁니다. 예: "하위 에이전트를 쓸 수 있으면 diff 리뷰를 위임하고, 아니면 새 세션에서 아래 프롬프트로 리뷰한다."
- 스크립트 경로는 스킬 루트 기준 상대경로로 씁니다(`scripts/x.py`). 대화형 입력을 받지 않고, `--help`를 제공하고, 구조화된 출력을 냅니다(표준 `using-scripts` 지침).
- 초기 core 스킬은 기존 Claude 전용 4종을 중립화해 이식합니다: `planning-changes`, `verifying-changes`, `writing-specs`, `authoring-skills`. 반박 리뷰는 에이전트 정의 대신 `reviewing-changes` 스킬로 만듭니다.

### 4.3 MCP 정본 (`.agents/mcp.json`)
```json
{
  "servers": {
    "github": { "transport": "http", "url": "https://api.example.com/mcp", "headers": { "Authorization": "Bearer ${env:GITHUB_TOKEN}" } },
    "db":     { "transport": "stdio", "command": "npx", "args": ["-y", "@example/db-mcp"], "env": { "DB_URL": "${env:DB_URL}" } }
  }
}
```
- 비밀은 `${env:NAME}` 참조로만 씁니다. 리터럴 비밀이 들어 있으면 검증에서 실패합니다.
- 어댑터는 각 도구의 파일·키·변수 문법으로 변환하고, 지원하지 않는 transport는 경고 후 건너뜁니다.

### 4.4 정책 — 중립 프로토콜
두 종류로 나눕니다. 강제할 수 있는 지점이 다르기 때문입니다.

| 종류 | 언제 | 어디서 강제 | 도구 의존 |
| --- | --- | --- | --- |
| **command** | 에이전트가 셸 명령을 실행하기 전 | 훅을 지원하는 도구의 shim | 있음 (없는 도구는 건너뜀) |
| **change** | 변경 내용이 커밋·푸시되기 전 | git pre-commit, CI | **없음** |

명령 정책 프로토콜(도구 무관):
```text
stdin : {"event": "pre_command", "command": "<shell string>", "cwd": "<path>"}
stdout: {"decision": "allow" | "ask" | "deny", "reason": "<text>"}   (결정이 없으면 출력 없음)
exit  : 0 (정책 스크립트 오류는 0이 아닌 코드 → shim이 '경고 후 통과'로 처리)
```
어댑터의 shim은 도구의 훅 입력을 이 형식으로 바꾸고, 결과를 도구의 응답 형식으로 되돌립니다. 기존 `claude-code/plugins/omni-guardrails/scripts/guard-bash.sh`의 판정 로직과 테스트 케이스는 그대로 이식합니다.

### 4.5 검증 진입점
- 프로젝트는 하나의 검증 명령을 정해 `.agents/omni.json`의 `verify`와 AGENTS.md Commands에 기록합니다. 예: `make verify`, `npm run verify`, `scripts/verify`.
- 에이전트(스킬 `verifying-changes`), 사람, CI가 **같은 명령**을 씁니다.

### 4.6 어댑터 계약
```text
입력 : AGENTS.md, .agents/**, .agents/omni.json
출력 : 해당 도구가 읽는 파일들 (헤더 또는 manifest로 생성물 표시)
규칙 : 멱등 · 정본 외 파일은 수정하지 않음 · 도구가 지원하지 않는 기능은 경고 목록으로 보고
       · `--check` 모드는 쓰지 않고 drift만 보고 (CI용)
```
| 어댑터 | 1차 범위 | 확인 상태 |
| --- | --- | --- |
| claude-code | CLAUDE.md(`@AGENTS.md`), `.claude/skills/` 복사, metadata 번역, command 정책 → PreToolUse shim, `.mcp.json` | ✅ 공식 문서 + 기존 `claude-code/`로 실측 |
| gemini-cli | `.gemini/settings.json` `context.fileName`, MCP | AGENTS.md 설정 ✅ / 나머지 ⚠️ |
| codex | 스킬 경로, MCP(`config.toml`) | ⚠️ |
| copilot / vs code | 스킬 경로, `.vscode/mcp.json` | ⚠️ |
| cursor | `.cursor/mcp.json`, 스킬 경로 | ⚠️ |

⚠️ 항목은 해당 어댑터를 구현할 때 각 도구의 공식 문서로 확인한 뒤 확정합니다.

## 5. 프레임워크 저장소 구조 (`universal/`)

```text
universal/
├── docs/            DESIGN.md (이 문서), STANDARDS.md
├── core/            프로젝트에 설치되는 정본 콘텐츠
│   ├── AGENTS.template.md
│   ├── skills/      중립 스킬 (Agent Skills 표준 + evals/)
│   ├── policies/    command/, change/ 정책 + 테스트
│   └── mcp/         mcp.json 스키마와 예시
├── adapters/        도구별 렌더러 (claude-code, gemini-cli, codex, copilot, cursor)
└── tools/           CLI: init · sync · check · validate · eval
```

CLI 동작:

| 명령 | 동작 |
| --- | --- |
| `omni init <project>` | core를 설치하고 `omni.json`·`omni.lock`을 만듭니다. 기존 파일은 덮어쓰지 않습니다. |
| `omni sync [--check]` | 활성 어댑터를 실행합니다. `--check`는 drift만 검사합니다. |
| `omni update` | core 새 버전을 반영합니다. lock 해시로 로컬에서 수정한 파일을 감지해 보존하고, 충돌을 보고합니다. |
| `omni validate` | 스킬 표준 + 합집합 이름 규칙, 중립 서술 린트(P6), mcp.json 스키마·리터럴 비밀, AGENTS.md 길이를 검사합니다. |
| `omni eval <skill> --agent <cmd>` | `evals/evals.json`을 스킬 있음/없음으로 실행합니다. 에이전트 실행은 주입식 명령으로 받아 도구 중립을 유지합니다. |

## 6. 보안

- 스킬과 정책은 실행 코드입니다. 외부 스킬은 리뷰 후 들여오고, 버전과 해시를 lock에 고정합니다.
- 비밀 파일 읽기 차단은 각 도구의 권한 설정으로 렌더합니다(가능한 도구만). 비밀 유출의 **최종 차단**은 change 정책(pre-commit + CI)이 맡습니다.
- MCP 설정에는 env 참조만 허용합니다.

## 7. `claude-code/`와의 관계와 로드맵

`claude-code/`는 이 설계에서 **Claude Code 어댑터가 출력해야 할 결과물의 실측 참조 구현**입니다.

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| 0 (현재) | 설계 문서, 표준 조사, 폴더 뼈대 | 설계 합의 |
| 1 | core 콘텐츠: AGENTS 템플릿, 중립 스킬 5종 + evals, 정책 이식 + 테스트, `omni validate` | `skills-ref validate` + 자체 린트 통과 |
| 2 | `omni init/sync/check` + claude-code 어댑터 | 어댑터 출력으로 기존 `claude-code/` 기능을 재현. 이후 `claude-code/`는 생성물로 대체하거나 축소 |
| 3 | 추가 어댑터 (공식 문서 확인 후) | 도구별 실제 세션에서 스킬 로드 확인 |
| 4 | `omni eval` 하네스 | 2개 이상 도구 × 모델에서 스킬 있음/없음 비교 리포트 |

## 8. 결정이 필요한 사항

1. **CLI 구현 언어**: Python(설치 쉬움) / Node(npx 배포) / Go(단일 바이너리)
2. **1차 지원 도구 우선순위**: claude-code 다음에 어느 도구부터 구현할지
3. **배포 방식**: CLI 복사 + lock(권장) / git submodule / 패키지 매니저
4. **생성물 커밋 기본값**: 커밋(권장, 클라우드 세션 호환) / gitignore
